# Research notes and reference data

The investigation that the viewer is built on: how Qubic contract state is laid out in memory, how the QPI containers
store their data, what a state file is. The reports are written against the core versions v1.303.2 (epoch 229) and
HEAD of that time (v1.306.0); file and line numbers refer to those checkouts. Paths and script names inside the reports
point at the original research workspace, which no longer exists: the useful parts live in `reference/` and `data/`.

| | |
| --- | --- |
| [01-qpi-types-and-containers.md](01-qpi-types-and-containers.md) | MSVC x86-64 layout rules, `Array`, `HashMap`, `HashSet`, `Collection`, `LinkedList`, K12, identities; the algorithms of `native/decode` |
| [02-qpi-proposals.md](02-qpi-proposals.md) | `ProposalVoting` storage and its decoding |
| [06-state-files.md](06-state-files.md) | `contractNNNN.EEE` and the sibling epoch files, how the node writes them, how to watch them live |

| [reference/](reference/) | stdlib-only Python reference decoders (layout model, containers, identities, proposals) |
| [data/](data/) | ground truth used by the native tests (see below) |

## data/ (read by the tests, do not move)

| File | Used by |
| --- | --- |
| `contract-layouts-a.json`, `contract-layouts-b.json` | field offsets and sizes of every contract state type in v1.303.2 and HEAD, computed independently (Python model, checked against g++); `native/cpp` and `native/decode` tests |
| `contract-layouts-a.oracle.*.txt` | the same, as printed by a g++ probe compiled from the real headers; `native/cpp` tests |
| `identity_vectors.txt` | identities with public keys generated by the core itself; `native/support`, `native/decode` tests |
| `digest_229.txt` | K12 digests of the 29 epoch-229 state files as computed by the core; `native/support`, `native/service` tests |

## reference/

`decode_real.py <state dir>` decodes the real epoch-229 files with `qpi_layout.py` (container algorithms),
`qubic_identity.py` (K12 + identity codec) and `contract_states_229.py` (hand transcribed state structs) and prints
consistency checks; `p02_decode_proposals.py` does the same for the proposal containers. They are the executable form
of reports 01 and 02 and an independent check of `native/decode`; they are not needed to build or run the viewer.
